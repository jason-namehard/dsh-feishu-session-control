# 当前需求基线

最后确认：2026-09-09。

## Session 与飞书

1. Web 创建 session 默认与飞书无关，消息不推送飞书。
2. 飞书聊天首次普通消息自动创建并连接独立 session。
3. 首次连接和 `/use` 默认半衔接。
4. `/use <alias>` 不回填历史。
5. `/switch` 用卡片选择半衔接或完整衔接。
6. 半衔接只返回飞书发起回合的结果；Web/TUI 独立回合不抄送。
7. 完整衔接额外抄送 Web/TUI 新消息和回复。
8. `/detach` 只解除飞书连接，保留 DSH session。
9. 一个普通群聊对应一套共享 session；只消费新事件，不遍历全量群历史。

## Session 生命周期

1. `/sessions` 跨工作空间列出别名、原生标题、状态和当前对话。
2. 新 session 使用稳定 `MMDD-N` 别名。
3. `/rename` 同步 DSH Web UI 标题。
4. `/delete` 进入回收站，别名和其他编号不重排。
5. `/purge` 二次确认后永久删除并移除别名。
6. Web 只在回收站展示永久删除入口。

## 审批

1. 插件不增加无意义的工具审批。
2. DSH 在电脑端不需要审批的操作，飞书不得额外卡住。
3. DSH 原生需要审批时，Web 和飞书均可回答同一请求。
4. 任一端批准即可继续。
5. 真实方案选择使用正文完整选项 + 短按钮，不把普通工具调用伪装成方案选择。

## 运行生命周期

1. DSH 停止后飞书同步断开。
2. 不存在 Guardian、离线接管、自动启动或自动重启。
3. 托盘仅提供用户主动打开、重启和退出 DSH。
4. 插件更新优先由 `dsh-hot-installer` 热重载，失败再显式重启。

## 移动端

1. 默认不展示 reasoning。
2. 收到消息用表情确认，不发送占空间的大“思考中”卡片。
3. 执行完成只发送清晰最终结果；失败/超时/中断必须有简短终态。
4. 卡片按钮点击后必须显示已完成状态并撤回原待选卡。
